# 후반부 안정영역 계산: 원래 ID526~1050

이 브랜치는 `carsim_fullcar`의 후반부525조건만 담당합니다. ID1~525는 별도 작업이며 여기서 계산하거나 수정하지 않습니다.

- [후반부 진행률](progress.json): 자동 업로드 시점의 완료 수와 실제 조건 ID입니다.
- [실행 서명](run_binding.json) · [런타임 검사](runtime_validation.json) · [첫 실제 결과 검사](first_case_verification.json)
- 첫 결과526: [MAT](../../regions/case_0526.mat) · [그림](../../images/case_0526.png) · [이미지 서명](../../images/case_0526.json)

원래34상태 모델·물리 데이터·보정·검증된 MEX를 그대로 사용합니다. GNU Octave10.3.0, RK4 0.0005초, 관측0.001초,61×121격자이며 5초·10초 판정과 실제 셀 중심점 적분을 유지합니다. MATLAB/CarSim 실행기를 실행했다고 표시하지 않습니다.

첫 조건의 실제 적분·MAT·이미지 검증 후 결과를 먼저 게시합니다. 이후 자동 업로드는 완료된 조건마다(1조건당) 수행합니다. GitHub 진행률은 마지막 업로드 시점의 기록입니다. 원본 컨텍스트·로그·체크포인트·PID파일은 게시하지 않습니다.

`525/525`는 이 후반부의 완료이며 전체1050개 완료가 아닙니다. 두 절반의 모든 조건·입력·엔진·수치·이미지를 검증하기 전에는 통합 LUT를 최종화하거나 누락 결과를0으로 채우지 않습니다.

## 개별 조건 자동 업로드

현재 실행기가 `--publish-every 1`로 계산과 게시를 함께 처리합니다. 조건마다 MAT·PNG·이미지 서명 검사를 통과한 뒤 해당 브랜치에 push하고 원격 SHA를 확인합니다. 별도 업로드 감시자는 사용하지 않습니다.

[계산 진행률](progress.json) · [조건별 업로드 현황](per_case_upload.json) · [재개 기록](recovery_report.json)

프로세스가 종료되면 유효한 완료 결과와 체크포인트를 보존하며 같은 명령으로 재개합니다. 재개 명령에도 반드시 `--publish-every 1`을 사용합니다. [최근 재개 기록](recovery_report.json)은 원인을 추정해 단정하지 않고 실제 확인한 상태만 기록합니다.
